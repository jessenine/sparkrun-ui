# BUG-20260808T062446: Host metrics show cards for hosts not returning metrics

## Problem

The cluster monitor shows **3 host cards** when only 2 systems are actually up and returning metrics. Host cards should only be shown for systems that are running and returning metrics; a host that is down, unreachable, or returning no sample must not appear as a card.

**Actual behavior**: Monitor page renders a host card for every key in the tick's `hosts` map, including hosts that produced no metrics (e.g., an SSH/collection failure or an empty/missing sample).

**Expected behavior**: Only hosts that are actively returning metrics get a card (2 cards in the reported case, not 3), and the host-count badge reflects that.

**How to reproduce**: Run the cluster monitor across 3 configured hosts where 1 host is down or cannot be reached/collected. The monitor stream emits 3 host entries for that tick; all 3 appear as cards even though only 2 returned any sample data.

## Root Cause Analysis

The stream request/response flow is:

1. The client (`MonitorLive`) calls `rpc.monitor.stream` and renders one card per entry of `tick.hosts` via `Object.entries(tick.hosts)`.
2. The server `stream` handler normalizes each raw sparkrun tick (array format `[{ host, sample, error, ... }]` or flat-record format `{ host: {...} }`) with `normalizeMonitorOutput`.

**Root cause**: `normalizeMonitorOutput` inserts host entries into the result `hosts` map **unconditionally**:
- In the **array format** branch, a host entry is added even when its `error` field is non-null/empty-string (i.e., that host failed to be collected / is not returning metrics), and even when its `sample` is null, undefined, or an empty object (no metrics). The code explicitly substitutes an empty object for a missing sample rather than skipping the host.
- In the **flat-record format** branch, any host whose value is an object is kept, including an empty `{}`.

Because `normalizeMonitorOutput` never inspects the per-host `error` field and never drops empty/missing samples, the "dead" host propagates into `tick.hosts` and is rendered as a card by `MonitorLive`.

The data contract (see module comment for the metrics collector) defines each host entry as `{ host, error: null|string, sample: {...}, ... }`, where a non-null `error` signals that host is not returning data. The normalizer ignores exactly that signal.

**Contributing factors**: The array-format branch has an explicit comment ("Handle null/undefined samples gracefully - use an empty object instead of skipping") that encodes the "keep the host" behavior; there is no corresponding "skip hosts that are not returning metrics" logic. There is also no prior regression in the normalizer — the filter was never implemented.

**Security impact**: NONE — no exploit path identified. This is a data-filtering/presentation defect with no privilege or integrity implications.

**Risk level**: Low — the change is a filtering condition in one normalization function; existing behavior for healthy hosts is unchanged.

## TDD Fix Plan

The fix lives in the normalization layer (the public contract between sparkrun output and the UI), so tests assert on `normalizeMonitorOutput` output and keep rendering untouched.

1. **RED**: Add a unit test asserting that, for the **array format**, a host entry with a non-null `error` yields no card — i.e., `normalizeMonitorOutput([{ host: "dead", error: "ssh: connect refused", sample: {...} }, { host: "alive", error: null, sample: {...} }]).hosts` contains only `alive`.
   **GREEN**: In the array-format branch of `normalizeMonitorOutput`, `continue` (skip) when `entry.error` is non-null/non-empty, and `continue` when `sample` is null/undefined or an empty object (no metrics). Only hosts with a present, non-empty sample are inserted.
   **verify**: `npx vitest run lib/rpc/procedures/monitor-stream.test.ts`

2. **RED**: Add a unit test asserting that, for the **flat-record format**, a host whose value is an empty object `{}` yields no card — `normalizeMonitorOutput({ timestamp, hosts: { dead: {}, alive: { cpu_usage_pct: "10" } } }).hosts` contains only `alive`.
   **GREEN**: In the flat-record branch of `normalizeMonitorOutput`, skip any `hostData` that is empty (no keys) or non-object.
   **verify**: `npx vitest run lib/rpc/procedures/monitor-stream.test.ts`

**REFACTOR**: If the two branches now share the same health predicate ("host has a non-empty metrics sample"), extract a small helper (e.g., `isLiveHostSample(sample))` used by both branches to keep the skip logic in one place.
